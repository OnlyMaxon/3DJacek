# 3DJacek — архитектура

Сканируешь комнату телефоном → получаешь её 3D-модель → ставишь внутрь мебель и смотришь, как
встанет. Без регистрации, без сервера, всё лежит в памяти телефона. Только iOS, только TestFlight.

---

## 1. Что определяет всю архитектуру

Три ограничения, из которых следует остальное:

**LiDAR обязателен.** Сканирование делает Apple RoomPlan, а он работает только на устройствах с
LiDAR: iPhone 12 Pro и новее (именно Pro/Pro Max), iPad Pro 2020+. На обычном iPhone фреймворк
просто недоступен, в симуляторе — тоже. Значит на входе в приложение нужен честный гейт
возможностей, а не падение в рантайме.

**Нет Expo Go.** RoomPlan — нативный код, которого нет в клиенте Expo Go. Вся разработка идёт
через собственный dev client (`eas build --profile development`), который ставится на устройство
один раз и дальше принимает JS по сети.

**Оффлайн и анонимно.** Нет аккаунтов, нет аналитики, нет загрузки сканов. Отсюда: нет слоя API,
нет кэша запросов, нет авторизации. Источник правды — файловая система устройства.

## 2. Решения и почему именно так

| Решение | Почему |
|---|---|
| Сканирование: Apple RoomPlan через `expo-roomplan` | Нативно, оффлайн, бесплатно, сразу даёт параметрическую геометрию. Писать свой Swift-враппер поверх `RoomCaptureView` — та же работа, что уже сделана в MIT-пакете. |
| Экспорт: `PARAMETRIC` + JSON | `MESH` даёт честную, но грязную триангуляцию. `PARAMETRIC` — чистые плоскости и боксы, что идеально ложится и на ч/б стиль, и на наш three.js-рендер. |
| Рендер: читаем **JSON**, не USDZ | У three.js нет загрузчика USDZ. Зато JSON `CapturedRoom` — это список боксов с матрицами, из которого сцена собирается в пару десятков строк, детерминированно и без парсинга бинарников. USDZ всё равно сохраняем — для системного Quick Look и будущего экспорта. |
| Вьюер: `three` + `@react-three/fiber` на `expo-gl` | Декларативная сцена, React-овый стейт, живой драг мебели через жесты. Альтернатива — нативный SceneKit-модуль, но это ещё один Swift-слой ради того же результата. |
| Стейт: `zustand` | Сцена мутируется часто (драг мебели — десятки апдейтов в секунду). Нужен стор без контекст-ререндеров всего дерева. |
| Навигация: `expo-router` | Файловый роутинг, типизированные маршруты, стабилен в SDK 58. |
| Хранение: файлы + JSON-индекс | Сканов будут единицы, не тысячи. SQLite здесь — лишняя зависимость и миграции на пустом месте. |

что выше. Android не поддерживается и не планируется: в `app.config.ts` стоит `platforms: ['ios']`.

> Риск: `expo-roomplan` собран против SDK 53. peerDeps у него `*`, нативная часть тонкая
> (один view + один модуль), но Expo Modules 2.0 в SDK 58 — мажорное изменение.
> Проверяется первым же dev-билдом; план Б — вендорим пакет в `modules/` и правим под новый API.

## 4. Дерево

```
src/
  app/                        экраны, expo-router (роуты только здесь)
    _layout.tsx               корневой стек, тема, провайдеры
    index.tsx                 главный: логотип и кнопка «Снять комнату»
    unsupported.tsx           гейт: устройство без LiDAR
    scans/
      index.tsx               список сохранённых сканов
      [id].tsx                3D-вьюер + меню «+» + автосейв

  core/
    device.ts                 проверка возможностей (LiDAR, версия iOS)
    ids.ts                    генерация id
  scan/
    useScanner.ts             подписка на нативное событие → запись на диске
    captured-room.ts          типы сырого JSON от RoomPlan
    parse.ts                  сырой JSON → RoomModel (нормализация)
  storage/
    types.ts                  ScanRecord, RoomModel, PlacedItem, Surface
    paths.ts                  раскладка каталогов на диске
    scans-repo.ts             CRUD сканов: индекс + файлы
  scene/
    Viewer.tsx                Canvas, свет, проводка жестов
    controls.ts               камера, рейкаст, драг — вся логика взаимодействия
    RoomMesh.tsx              стены/пол/проёмы из RoomModel
    PlacedFurniture.tsx       расставленные предметы
    EdgedBox.tsx              бокс с рёбрами — базовый кирпич сцены
  furniture/
    catalog.ts                каталог: id, имя, габариты
    primitives.ts             габариты → набор боксов (стул, стол, диван…)
    FurnitureSheet.tsx        панель выбора по кнопке «+»
  store/
    editor-store.ts           zustand: текущая сцена и её мутации
  ui/
    theme.ts                  токены ч/б + палитра сцены
    Logo.tsx                  куб с вазой, SVG
    Button.tsx                Button и IconButton

assets/                       icon.png, splash-icon.png (генерятся скриптом)
scripts/make-icons.mjs        логотип → PNG, `npm run icons`
architecture.md  README.md  AGENTS.md
app.config.ts  eas.json  eslint.config.js  tsconfig.json  metro.config.js
```

В `metro.config.js` одна правка, и она обязательная: `three` принудительно разрешается в
ESM-сборку. CJS-сборка three 0.187 на старте зовёт `process.emitWarning`, которого в React Native
нет, а `@react-three/fiber` подключает three через `require()` — Metro по условию `"require"`
берёт именно её, и приложение падает на импорте сцены. Побочный плюс: один экземпляр three на
приложение вместо двух.

Правило зависимостей — строго в одну сторону: `app/` → `scene · furniture · ui` → `store` →
`scan · storage` → `core`. Слой никогда не импортирует то, что выше. `scene` ничего не знает про
стор: экран передаёт ему данные пропсами и забирает изменения колбэками.

Импорты — через алиас `@/*` на `src/*` (`tsconfig.json` + поддержка путей в Metro).

## 5. Поток данных

```
  Пользователь открыл приложение
            │
            ▼
   core/device.ts — есть LiDAR?
       нет ──────────────────────► app/unsupported.tsx
       да
            ▼
   app/index.tsx → startCapture()
   Apple показывает свой полноэкранный UI, пользователь обходит комнату
            │  закрыл модалку
            ▼
   одно нативное событие onDismissEvent: { status, jsonUrl, scanUrl }
            │
            ▼
   scan/parse.ts    сырой CapturedRoom → RoomModel
   (нормализация: матрицы → позиция + поворот, метры, Y вверх, ноль в центре пола)
            │
            ▼
   storage/scans-repo.ts
   пишет room/scene/raw.json и копирует usdz в Documents/scans/<id>/,
   добавляет строку в index.json
            │
            ▼
   app/scans/[id].tsx
   RoomModel → scene/Viewer (белая коробка комнаты)
            │
            ▼
   «+» → furniture/catalog → PlacedItem в editor-store
   драг/вращение мутируют стор → автосейв в scene.json через 400 мс
```

Важное следствие: **прогресса сканирования у нас нет и быть не может**. Пока открыт нативный UI
Apple, приложение не получает ни одного события — только финальное, на закрытии. Поэтому
«собираем модель» показывается уже после модалки, на этапе разбора JSON.

Взаимодействие во вьюере — четыре жеста, и решение принимается в момент касания одним рейкастом:
палец по пустому месту вращает камеру, палец по предмету тащит его по полу, два пальца — зум,
тап по пустому — снять выделение. Поворот предмета сделан кнопками по 15°, а не жестом: жест
вращения двумя пальцами конфликтовал бы с зумом.

## 6. Модель данных

Сырой RoomPlan отдаёт то, что удобно Apple: матрицы 4×4 column-major, категории Swift-энамами.
Мы это один раз нормализуем на входе, и дальше по приложению ходит только своя модель.

```ts
// Нормализованная комната. Метры, правая система координат, Y вверх, начало — центр пола.
type RoomModel = {
  version: 1;
  bounds: { width: number; depth: number; height: number };
  surfaces: Surface[];   // стены, окна, двери, проёмы, пол
  detected: Detected[];  // мебель, которую RoomPlan нашёл сам
};

type Surface = {
  id: string;
  kind: 'wall' | 'window' | 'door' | 'opening' | 'floor';
  size: Vec3;            // w, h, d
  position: Vec3;        // центр элемента
  rotationY: number;     // радианы; RoomPlan всегда ставит элементы вертикально
  confidence: 'low' | 'medium' | 'high';
};

// То, что пользователь поставил сам.
type PlacedItem = {
  id: string;
  catalogId: string;     // ключ в furniture/catalog
  position: Vec3;        // y всегда 0 — мебель стоит на полу
  rotationY: number;
  scale: number;
};

type ScanRecord = {
  id: string;
  name: string;
  createdAt: string;     // ISO
  room: RoomModel;
  items: PlacedItem[];
  usdzPath: string | null;
};
```

Про парсинг отдельно: JSON `CapturedRoom` кодирует категории двумя разными способами — у объектов
это строка (`"chair"`), а у поверхностей, где у Swift-энама есть ассоциированные значения, это
объект (`{"door":{"isOpen":false}}`). Парсер обязан понимать оба варианта и не падать на
неизвестной категории, иначе новая версия iOS сломает открытие сканов.

## 7. Хранение

```
<Documents>/
  index.json                список сканов без тяжёлых полей: id, name, createdAt
  scans/
    <id>/
      room.json             нормализованный RoomModel
      scene.json            PlacedItem[] — расставленная мебель
      raw.json              сырой CapturedRoom, на случай переразбора
      room.usdz             экспорт Apple, для Quick Look и шаринга
```

Почему так: `index.json` читается при открытии списка и остаётся маленьким; тяжёлая геометрия
грузится только когда скан реально открыли. `scene.json` пишется отдельно от `room.json`, чтобы
автосейв мебели не перезаписывал геометрию комнаты. `raw.json` — страховка: если улучшим парсер,
старые сканы можно пересобрать без повторного обхода комнаты.

Записи атомарные: пишем в `*.tmp`, затем переименовываем. Приложение могут убить в любой момент.

## 8. Дизайн

Чистая чёрно-белая система, никаких акцентных цветов:

```
bg       #000000     фон
surface  #0E0E0E     карточки, шиты
line     #2A2A2A     границы, каркас
textDim  #8A8A8A     подписи
text     #FFFFFF     основной текст
```

Комната рендерится как белый каркас: пол — тёмная заливка с сеткой, стены — полупрозрачные
плоскости с белыми рёбрами, мебель — светлые боксы с контрастными рёбрами. Выделенный объект
инвертируется. Такой «white-box» вид — не компромисс, а осознанный стиль: он честно показывает
то, что реально знает RoomPlan, и не притворяется фотореализмом.

Логотип: контур изометрического куба, внутри по центру силуэт вазы. Нижнее вертикальное ребро
куба не рисуется — иначе оно режет вазу пополам. Компонент `ui/Logo.tsx`, а иконку и splash
печёт `scripts/make-icons.mjs` (`npm run icons`) через resvg. Пути в скрипте продублированы
сознательно: тащить react-native-svg в сборочный скрипт дороже, чем держать две копии
одного пути из шести команд.

Мебель — параметрические примитивы в коде, а не скачанные модели. Готовых бесплатных API с
мебелью нет, а боксы из `BoxGeometry` в ч/б стиле выглядят ровно так, как надо, весят ноль и
имеют честные габариты в сантиметрах. Стартовый набор: стул, стол, диван, шкаф, тумба, лампа.

## 9. Нативный слой

Своего Swift-кода не пишем — `expo-roomplan` закрывает всё. Нужна только конфигурация:

- `NSCameraUsageDescription` — внятный текст, Apple режет ревью за шаблонный
- `ITSAppUsesNonExemptEncryption: false` — иначе App Store Connect спросит про экспортное
  шифрование на каждом билде
- privacy manifest: `NSPrivacyCollectedDataTypes: []` плюс объявленные «required reason» API —
  file timestamp (`C617.1`) и disk space (`E174.1`), их трогает expo-file-system
- `deploymentTarget: '16.4'` через `expo-build-properties`
- в `app.config.ts` платформы = `["ios"]`

Всё декларативно в `app.config.ts`, папку `ios/` в репозиторий не кладём — её генерит
`expo prebuild` на стороне EAS. Так проект остаётся обновляемым между SDK.

## 10. Сборка и TestFlight

```
eas build --profile development --platform ios   # dev client, один раз на устройство
npx expo start --dev-client                      # цикл разработки
eas build --profile production --platform ios    # ipa для стора
eas submit --platform ios --latest               # загрузка в TestFlight
```

Профили в `eas.json`:
- `development` — `developmentClient: true`, internal distribution, для своего устройства
- `preview` — release-сборка, internal, проверить производительность без TestFlight
- `production` — store distribution, автоинкремент `buildNumber`

Идентификаторы: bundle `com.jacek.room3d`, slug `jacek-3d`, имя «Jacek 3D». Меняются одной
строкой в `app.config.ts` до первого сабмита.

Credentials ведёт EAS: при первом `eas submit` он сам создаёт App ID, провиженинг и ключи в
подключённом Apple-аккаунте. Mac не нужен, сборка идёт на облачных macOS-воркерах.

## 11. Фаза 2

Заложено, но не делаем сейчас:

- **Живой AR.** Нативный модуль на ARKit + RealityKit: мебель стоит на реальном полу через
  камеру. Точка расширения — `PlacedItem` уже в метрах относительно центра пола, этого
  достаточно, чтобы отдать координаты в AR-сессию без пересчёта модели.
- **Мультирум.** RoomPlan с iOS 17 умеет склеивать несколько комнат (`StructureBuilder`).
  `RoomModel.version` на месте именно для такой миграции.
- **Шаринг.** USDZ уже сохраняется — отдать его в системный share sheet это один экран.
- **Поддержка не-Pro устройств.** Ручной обмер по ARKit-плоскостям как фоллбек для гейта.

## 12. Чего осознанно нет

Нет бэкенда, нет авторизации, нет пушей, нет Android, нет светлой темы (тема одна — чёрная),
нет облачного бэкапа. Каждое из этого — отдельный слой сложности, и ни одно не нужно, чтобы
снять комнату и поставить в неё стул.
